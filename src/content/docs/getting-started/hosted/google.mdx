<TabItem label="Colab">

Open a notebook in Google Colab and run this setup cell before importing analysis packages. Run it again whenever Colab assigns a new runtime.

The [setup script](https://github.com/neurodesk/neurocommand/blob/main/googlecolab_setup.sh) installs the container tools, Lmod, DataLad and git-annex, mounts the Neurodesk software repository, and writes the environment settings used by the notebook. It also keeps the Python dependencies compatible with Colab.

```python
import json
import os
from pathlib import Path
import subprocess
import sys

setup_url = 'https://raw.githubusercontent.com/NeuroDesk/neurocommand/main/googlecolab_setup.sh'
subprocess.run(['curl', '-fsSL', setup_url, '-o', '/content/googlecolab_setup.sh'], check=True)
with open('/content/neurodesk-setup.log', 'w') as log:
    result = subprocess.run(
        ['bash', '/content/googlecolab_setup.sh'],
        env=dict(os.environ, NEURODESK_COLAB_PYTHON=sys.executable),
        stdout=log, stderr=subprocess.STDOUT,
    )
if result.returncode:
    print(Path('/content/neurodesk-setup.log').read_text()[-6000:])
    result.check_returncode()
os.environ.update(json.loads(Path('/content/neurodesk-colab-env.json').read_text()))
print('Neurodesk is ready. Full log: /content/neurodesk-setup.log')
```

The final `os.environ.update(...)` imports the settings into the running Python kernel. Running the shell script alone cannot change the notebook's environment. If setup fails, the cell displays the end of the installation log and stops.

Once this setup is completed, you can list the available Neurodesk applications like this:

```python
import lmod
await lmod.avail()
```

and use applications like this:

```python
await lmod.load('fsl/6.0.4')
!bet
```

DataLad and git-annex are ready after setup; no separate installation cell is needed. Check their versions with:

```python
!datalad --version
!git annex version
```

Use lowercase `datalad` for the command. The script installs DataLad separately from Lmod so an unavailable Ubuntu DataLad package cannot prevent Neurodesk modules from loading.

<TabItem label="Cloud Shell">

This also works in a Google Cloud Shell, for example for an interactive tutorial via `cloudshell launch-tutorial`.

First, run this:

```bash
curl -J -O https://raw.githubusercontent.com/neurodesk/neurocommand/main/googlecloudshell_setup.sh
chmod +x googlecloudshell_setup.sh
./googlecloudshell_setup.sh
```

Then use a `tutorial.md` like:

````markdown
# My first fsl tutorial in Cloud Shell

## Step 1: Say Hello
Run the following command to print a message:

```bash
module use /cvmfs/neurodesk.ardc.edu.au/neurodesk-modules/*
ml fsl
bet
```
````

The tutorial can be started via:

```bash
cloudshell launch-tutorial tutorial.md
```

Or via a URL:

```text
https://ssh.cloud.google.com/cloudshell/editor?cloudshell_git_repo=REPO_URL&cloudshell_tutorial=path/to/tutorial.md
```

where `cloudshell_git_repo` is the URL of the Git repository to clone and `cloudshell_tutorial` is the relative path to the markdown file inside that repo.
