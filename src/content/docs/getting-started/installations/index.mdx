This section contains guides for running Neurodesk on specific systems. Choose your cluster, hosted service, or local operating system below. If you are still deciding how to run Neurodesk, start with [Choose your setup](/getting-started/).

## University HPC clusters

These guides cover each cluster's way of accessing Neurodesk tools. You need an account on the relevant system.

| Guide | Institution | What the guide covers |
| --- | --- | --- |
| [Bunya](/getting-started/installations/bunya/) | University of Queensland | Use preinstalled Neurodesk modules in interactive jobs and Jupyter notebooks. |
| [Great Lakes](/getting-started/installations/greatlakes/) | University of Michigan | Set up Neurocommand for desktop sessions and use tool modules in Jupyter notebooks. |
| [Sherlock](/getting-started/installations/sherlock/) | Stanford University | Run container tools and Slurm jobs, use JupyterLab or a full Neurodesktop session, and manage shared installations. |
| [UCSF CoreHPC](/getting-started/installations/ucsf/) | University of California, San Francisco | Start and reconnect to Neurodesktop with connection scripts for macOS and Windows. |
| [Palmetto](/getting-started/installations/palmetto/) | Clemson University | Load preinstalled Neurocontainers, submit Slurm jobs, use graphical tools through Open OnDemand, and transfer data. |

## Hosted desktops and imaging data

- [Nectar Virtual Desktop Service](/getting-started/installations/nectar/): Run Neurodesktop on a hosted virtual desktop available to Australian researchers.
- [XNAT at the Lucas Centre, Stanford](/getting-started/installations/xnat-lucas/): Transfer scanner data and other files to XNAT, then start Neurodesk for interactive processing.

## Local computers

The [Ubuntu 24.04 guide](/getting-started/installations/ubuntu2404/) covers Neurodesk App, Neurodesktop through Docker, Neurocommand, and direct container use on an Ubuntu computer.
